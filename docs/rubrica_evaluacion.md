# Criterios de evaluación del proyecto final

> Transcripción de `docs/originales/criterios_evaluacion.pdf`.
> Docente: M.Sc. Alejandro Molina — Ingeniería de Software, Universidad Cooperativa de Colombia, San Juan de Pasto.

| Criterio                   | Aspectos evaluados                                                                  | Porcentaje |
|----------------------------|-------------------------------------------------------------------------------------|-----------:|
| Comprensión conceptual     | Entendimiento del problema, interpretación física y/o matemática, respuestas a preguntas | 20 % |
| Evaluación individual      | Respuestas a preguntas, comprensión individual                                      | 20 % |
| Gráficos y análisis        | Calidad de gráficos, interpretación, uso en conclusiones                            | 20 % |
| Presentación               | Claridad, diseño, comunicación oral                                                 | 15 % |
| Conclusiones               | Calidad de conclusiones, reflexión crítica                                          | 15 % |
| Programación y lógica      | Lógica del algoritmo, pseudocódigo o diagrama de flujo, relación código–modelo      | 10 % |
| **Total**                  |                                                                                     | **100 %** |

## Lectura práctica de la rúbrica

- **40 % depende de entender y defender oralmente** (comprensión conceptual + evaluación individual). Cada integrante debe poder explicar las derivadas, el gradiente, el sistema normal y el Hessiano sin apoyo.
- **El código vale solo 10 %**, y se evalúa la *lógica* y su *relación con el modelo matemático*, no la cantidad de código. Hace falta incluir pseudocódigo o diagrama de flujo.
- **Los gráficos (20 %) deben usarse en las conclusiones**, no solo mostrarse: superficie, trazas, curvas de nivel, recta ajustada, residuos.
- **Las conclusiones (15 %) piden reflexión crítica**: limitaciones del modelo lineal, interpretación de RMSE/R² en el contexto de los datos.
